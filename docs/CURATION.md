# 诗词语料整理与发布门禁

本项目把“已进入 API 的运行语料”和“仍在整理的候选语料”严格分开。程序能够验证
JSON 结构、引用、异文与简繁记录是否自洽，但不能代替人对扫描页的辨字、作品身份
和作者归属判断。

当前 `v0.2.x` 的运行池仍是已经完成双版本核对的 50 首唐代绝句：

- 49 首以国家图书馆藏 1933 年春明书店本《唐诗三百首》为主见证，并以
  1705 年《御定全唐诗》相应卷次复核。
- 崔护《题都城南庄》不在上述 1933 年主本目录中，因此归入
  `supplemental-classics`；其主见证是 1933 年《本事诗》，核对本仍为
  《御定全唐诗》。
- 1933 年主选本中的全局目录位置尚未全部复核，相关成员明确标记为
  `positionStatus: pending`，API 不返回伪造的序号。

这 50 首只是迁移通用数据模型的已审核起点，不是完整《唐诗三百首》，也不包含
宋词。只有整本目录和每一篇正文都通过下述门禁后，项目才会分别发布并宣称
`v0.3.0` 完整收录指定 1933 年《唐诗三百首》，`v0.4.0` 完整收录指定
朱孝臧本《宋词三百首》。

## 公开仓库的数据结构

```text
corpus/
├── works/<dynasty>/<work-id>.json
├── editions/<edition-id>.json
├── collections/<collection-id>.json
└── normalization.json
```

每个作品文件保存：

- 简体、繁体题名与正文；
- 朝代、文类、体式、格律及可选词牌；
- 任意数量的序、段、阕和带稳定 ID 的行；
- 选本成员关系及已确认或待确认的原书位置；
- 作者归属状态；
- 扫描见证、页码、审核状态和审核方法；
- 以“行 ID + Unicode 半开区间”定位的异文选择；
- 无法安全套用全局规则时才出现的语境相关简繁覆盖。

机械、可复用的繁简映射集中放在 `normalization.json`，避免每个作品重复登记。
`go:embed` 直接嵌入整个 `corpus`；服务启动前执行全库校验，任何错误都会拒绝
启动。

## 来源和版本固定

### 唐诗

主本是国家图书馆藏 1933 年《唐诗三百首》扫描。公开仓库记录扫描文件的
SHA-256、Commons 文件页及固定描述页修订号；页码统一使用 PDF 一基页序，并同时
保留页面可见的印刷卷页信息。

固定修订的维基文库《唐诗三百首》只用于目录解析和机器差异报警，不直接作为
定本。出现差异、缺字或归属疑问时，再查《御定全唐诗》等第二扫描。每个已经进入
运行池的作品都必须保存两个见证的定位和逐项异文决定。

### 宋词

主本是朱孝臧《宋词三百首》上下册公版扫描；固定修订的维基文库页面用于机器
比较，疑义再查国家图书馆藏《宋词三百首笺》扫描。上述材料目前只存在于独立
工作台，尚未进入运行池。

“完整收录”按指定版本的实际目录定义，不预设作品数必然恰好等于 300。序、题注、
多阕、异体字和选本原署名都必须按所选版本处理。

## 独立工作台

原始扫描、OCR 和可重建图片不提交到公开仓库，而是保存在
`curated-poetry-api-workbench`：

```text
sources/originals/   原始扫描和固定数字文本
derived/             可重建页图、旋转图和接触表
ocr/                 仅用于定位和报警的 OCR 结果
staging/             尚未完成目视核对的候选作品
cache/               可重建缓存
blog-integration/    博客接口实验
```

`sources/manifest.json` 记录来源页、固定修订、SHA-256、许可标记、页码口径和重建
命令。工作台脚本接受 `--workbench` 或 `POETRY_WORKBENCH`，不得依赖本机绝对
路径。机器解析生成的候选必须标记为 `machine-derived/unreviewed`，不得直接复制
到 `corpus/works`。

## 单篇审核流程

1. 从 collection manifest 确认作品身份、选本署名和原书位置。
2. 目视打开主扫描，核对题名、作者、序或题注、各段正文及跨页范围。
3. 与固定机器文本比较；差异只用于提示人工复核。
4. 目视检查第二扫描，记录所有影响定本文字的异文及选择理由。
5. 建立繁体主文本和简体展示文本；通用转换引用集中规则，语境转换写作品覆盖。
6. 运行单篇增量检查。
7. 全库检查通过后，才把审核状态提升为 `primary-scan-reviewed` 并进入随机池。

作者不明或归属有争议时，保留选本原署名，并通过 `attributionStatus` 和说明
披露；不得把不确定结论写成事实。无法解决的缺字、身份或归属问题继续留在
`staging/`。

## 校验层级

本地修改少数作品时使用：

```bash
go run ./cmd/corpuscheck --files corpus/works/tang/<work-id>.json
```

改动 edition、collection 或全局 normalization 时，命令自动退化为全库检查。
普通 `--files` 路径不存在时会直接失败，防止拼写错误被误报为成功；只有处理 Git
变更列表里的删除或重命名时，才使用 `--allow-missing --files ...` 显式退化为全库
检查。普通 CI、标签发布和服务启动始终执行完整校验，包括：

- JSON 未知字段、ID、路径和重复作品；
- edition 固定修订、SHA-256、许可与见证引用；
- collection 成员、顺序状态、完整状态及期望数量；
- 作品结构、词牌、段落、稳定行 ID、标点和字符范围；
- 主文本、见证异文、简繁规则与作品级覆盖的一致性；
- 审核等级与证据完整性。

增量校验只缩短本地反馈时间，不能替代发布前的全库一致性检查。

## 许可和学术边界

古代原作属于公版；扫描文件页的具体权利标记和适用法域由使用者自行核验。本项目
不在公开仓库重新分发原始扫描。

本项目独立完成的转录、结构化元数据和异文整理以 CC0-1.0 提供。维基文库固定
版本只作比较来源，其页面贡献遵循该站点的许可条款。本项目是一份透明、可复核的
实用语料，不宣称学术权威校勘。
